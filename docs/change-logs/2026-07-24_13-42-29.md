# Backend Type Fixes and Frontend Page Cleanup

## What Changed

- Removed duplicate `has_incomplete_tasks` definitions from the goal repository and service.
- Replaced generic cursor `object` types with concrete datetime cursor tuples.
- Added typed goal summary and milestone repository return values.
- Serialized paginated task models into `TaskResponse` values explicitly.
- Guarded nullable task due dates before generating a range cursor.
- Moved task and goal HTTP requests into `frontend/src/api`.
- Moved Calendar state, cache, navigation, mutations, and virtualization behavior into `useCalendarController`.
- Moved Goals fetching, pagination, completion, deletion, and feedback into `useGoalsController`.
- Moved goal response types, deadline calculations, and rank styling into shared type, utility, and constant modules.
- Reduced `CalendarPage` and `GoalsPage` to layout and component composition.

## Why

Repeated method definitions hid the actual implementation and produced editor diagnostics. Loose cursor and ORM result types also prevented static analysis from proving that paginated response data was valid.

The frontend pages had accumulated API calls, calculations, constants, cache management, and mutation workflows alongside JSX. Extracting these responsibilities makes each layer easier to test and keeps the page components readable.
