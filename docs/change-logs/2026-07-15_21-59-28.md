# Production Readiness Update - 2026-07-15 21:59:28

## Summary

This update moves Leveling System from a personal local-only configuration to a production-oriented baseline suitable for a small public deployment. It does not move the Python backend or PostgreSQL database onto Sites; those services still require an external container host unless the backend is rewritten for the Sites runtime.

## Security Changes

- Removed the unauthenticated `/api/users` administration router, including public user listing, account mutation, EXP mutation, and deletion operations. These endpoints allowed complete account compromise on a public URL.
- Replaced browser JWT storage and callback query tokens with an HTTP-only session cookie. This prevents JavaScript and browser history from exposing the session token.
- Kept bearer-token authentication for the mobile app while applying the same expiry and revocation rules.
- Added a per-user session version. Logout increments it, invalidating previously issued browser and mobile tokens instead of only deleting a browser value.
- Added signed, expiring OAuth state and bound it to an HTTP-only browser cookie. This protects normal login and guest-account linking from login CSRF and state tampering.
- Require Google to report a verified email before creating or linking an account.
- Added production redirect URI restrictions for mobile OAuth.
- Added rate limits to guest creation, Google login/callback, and mobile authentication. Production guest login defaults to disabled.
- Added strict production startup checks for credentials, HTTPS URLs, and JWT secret strength. API documentation is disabled in production.
- Moved database credentials and connection URLs behind environment variables instead of fixed Compose production values.
- Added trusted-host, CORS, proxy, request-size, timeout, CSP, frame, referrer, content-type, and permissions protections.

## Data Integrity Changes

- Validate that every task `goal_id` belongs to the authenticated user on create and update.
- Scope goal task queries by both goal and user, preventing cross-account task injection.
- Replaced goal-list N+1 task loading with one user-scoped task query.
- Prevent direct task status injection through create/update requests. Completion, cancellation, failure, and overdue changes must use their transactional business flows.
- Prevent editing or rescheduling terminal tasks and reject invalid state transitions.
- Require all active goal tasks to be complete before the server marks a goal complete.
- Added bounded titles, descriptions, recurrence values, timezone offsets, local hours, and date-range validation.
- Added PostgreSQL foreign keys with cascade/set-null behavior and indexes for user, status, goal, due, completion, and failure queries.

## Reliability And Runtime Changes

- Added Alembic and a production baseline migration that upgrades existing local databases and initializes fresh databases.
- Removed schema creation and ad hoc alteration from API startup.
- Moved overdue processing out of the API process into a dedicated scheduler service.
- Added a PostgreSQL advisory lock, single-instance scheduling, catch-up execution, and one transaction for overdue penalties, recurring tasks, and perfect-day updates.
- Disabled SQL query echo by default and configured connection health checks and bounded pooling.
- Added live and database-ready health endpoints. Docker waits for backend readiness before starting the scheduler and frontend.
- Pinned backend dependencies and upgraded React Router to a production-audit-clean version.

## Frontend Changes

- Browser authentication now discovers the HTTP-only session through `/api/auth/me` and sends credentials on API requests.
- Removed legacy JWT values from local storage during session initialization/logout.
- OAuth callback now confirms the server session rather than reading a token from the URL.
- Fixed the existing TypeScript/ESLint check failures.
- Added route-level lazy loading so chart and feature pages do not inflate the initial JavaScript download.

## Tests Added

- Session expiry and revocation version claims.
- Direct task-state injection rejection.

## Deployment Boundary

For a public release, use HTTPS and a same-origin reverse proxy, disable guest login unless deliberately supported, configure the exact Google callback URL, use managed backups for PostgreSQL, and keep only one scheduler instance. Sites can host the frontend, but FastAPI, PostgreSQL, and the scheduler need external hosting or a separate Worker/D1 migration.
